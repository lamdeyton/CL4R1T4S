## 3. Gap 发现与修复

### G113 — "1.58 MB" 单位换算错误（5 处，跨 R1/R5/R6）

- **位置**（5 处）：
  - `/workspace/analysis/reports/01-inventory.md:12`（R1 总字节）
  - `/workspace/analysis/reports/05-quantitative.md:23`（R5 §1.1 全局总量表）
  - `/workspace/analysis/reports/06-synthesis.md:23`（R6 §1.1 核心总结）
  - `/workspace/analysis/reports/06-synthesis.md:54`（R6 §1.3 数据快照表）
  - `/workspace/analysis/reports/06-synthesis.md:803`（R6 结语）
- **错误**：原声明 `1,619,689（≈1.58 MB）`，"1.58 MB" 来自**混用二进制 KB（÷1024）与十进制 MB（÷1000）**的不一致计算：
  - 1,619,689 / 1024 / 1000 = 1.5817 → "1.58"（混用，错误）
  - 1,619,689 / 1024 / 1024 = 1.5447 → 1.54 MiB（纯二进制）
  - 1,619,689 / 1000 / 1000 = 1.6197 → 1.62 MB（纯十进制）
- **修复**：将 5 处 "1.58 MB" 修正为 "1.62 MB"（十进制），添加 R32 G113 校正注记。选择十进制而非二进制的依据：报告其他 KB 用法均为十进制——"150KB"=149.7KB（decimal）、"23KB"=23.0KB（decimal）、"122KB"=122.8KB（decimal），若用二进制则应为 146/22/120 KiB。统一为十进制 MB 与既有 KB 用法一致。
- **连接型性质**：R5 §1.1 是 "1.58 MB" 的源头，R1/R6 均继承此值，属跨报告连接型 gap

### G114 — R6 §2.1 "27 个月" 时间跨度与端点不匹配

- **位置**：`/workspace/analysis/reports/06-synthesis.md:114`（§2.1 趋势 1）
- **错误**：原声明 "3.5 Sonnet（23KB, 2024-06）→ Opus 4.7（150KB, 2026-04），**27 个月**增长 6.5 倍"，但 3.5 Sonnet（2024-06）到 Opus 4.7（2026-04）的实际跨度为 **22 个月**，非 27 个月。27 个月是全局观察窗（2024-03 至 2026-06），误用于此特定曲线。
- **实测**：2024-06 → 2026-04 = 22 个月（6+12+4=22）
- **对比 R5**：R5 §6 趋势解读 line 449 写 "两年增长 6.5×"（"两年"=24 个月为约数，可接受）；R6 改为 "27 个月" 是错误放大
- **修复**：将 "27 个月" 修正为 "22 个月"，添加 R32 G114 校正注记，说明与 R5 §6 "两年" 约数的关系
- **注意**：R6 其他 3 处 "27 个月"（§1.1 line 23、K1 line 27、§1.3 line 62）均指全局观察窗（2024-03 至 2026-06），正确，无需修改

## 4. 第 21 类审计方法论贡献

### 方法论：数值计算重推导全量验证

**审计对象**：报告中所有可从原始数据文件重新计算的数值声明

**4 维核对标准**：
1. **总量计算正确性**：`sum(field)` 从原始数据文件重推导，与报告声明精确比对
2. **倍数/比例计算正确性**：`A/B` 的商与报告声明的倍数比对
3. **单位换算一致性**：bytes→KB→MB 的换算应统一使用十进制或二进制，不可混用
4. **时间跨度与端点匹配性**：声明的月数/年数应与起止日期实际跨度匹配

**典型 gap 模式**：
- **单位换算混用**（G113）：÷1024（二进制）与 ÷1000（十进制）在同一计算中混用，导致中间值
- **时间跨度误植**（G114）：将全局观察窗的跨度误用于特定子曲线
- **端点文件混淆**（R27 G88/R29 G101 已校）：同一 vendor 的增长曲线可用不同端点文件（max bytes vs max lines），需明确标注

**可复现性要求**：所有重推导用 Python 脚本执行，脚本逻辑在迭代记录中完整记录，确保其他审计者可复现

**与其他审计类型的关系**：
- 第 21 类是第 17 类（方法论注记全量实测）的补充：第 17 类验证"方法描述"与"实际数据"一致，第 21 类验证"数值结果"与"原始数据"一致
- 第 21 类是第 14 类（跨报告数值声明全量验证）的深化：第 14 类检查同一数值在不同报告间一致，第 21 类检查数值本身的计算正确性
