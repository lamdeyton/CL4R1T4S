## 4. 第24类审计方法论贡献

### 4.1 方法论定义

**第24类审计 — 跨报告引用图完整性核对**：对报告集合中所有"指向另一报告章节"或"指向另一文件"的引用做全量解析验证，发现并修复以下三类问题：
1. **章节引用悬空**：`R{N} §X.Y` 中 X.Y 在 R{N} 不存在
2. **文件引用拼写错误**：`VENDOR/filename.ext` 中文件名拼写错误（如 `Pools` vs `Tools`）
3. **历史错误污染主文本**：已修复的错误仍残留在主文本中（而非仅在 correction note 中）

### 4.2 标准化核对流程

1. **正则提取**：用 `\bR[2-7]\s*§\s*([0-9A-Za-z.]+)` 提取所有章节引用
2. **章节索引构建**：用 markdown 标题正则构建每个 report 的 section set
3. **前缀匹配规则**：`5.1` 匹配 `5.1`、`5.1.x`，也匹配 `5`（父节）
4. **文件引用扩展名限定**：仅对带 `.txt/.md/.mkd` 的引用做严格匹配，避免 false positive
5. **历史错误隔离验证**：对每个未解析引用，确认其位置是否在 correction note 中（若是，则非新 gap）
6. **模糊匹配兜底**：对无扩展名 informal 引用，用 `difflib.get_close_matches` 做最近匹配验证

### 4.3 与第20类的区别

| 审计类型 | 关注对象 | 验证维度 |
|---|---|---|
| 第 20 类（R31） | 报告 → 源文件 | 行号引用真实性（如 `Bolt:10-27` 是否真有该行内容） |
| 第 24 类（R35） | 报告 → 报告 + 报告 → 文件 | 章节引用与文件引用的解析正确性 |

两者形成"报告内引用真实性 + 报告间引用图完整性"的二维覆盖。
